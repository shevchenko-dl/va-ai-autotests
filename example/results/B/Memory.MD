# Накопленный опыт тестирования

> Файл накапливает знания, полученные при работе с текущей задачей и конфигурацией. Прочитай его в начале работы и дополняй по завершении. Пустые секции можно удалять по мере заполнения.

## 🧠 Полезные знания о конфигурации
<!-- Особенности тестирования конкретных объектов конфигурации (справочники, документы, отчёты), специфичные для данной конфигурации шаги, известные проблемы и их решения. -->

- Заказ поставщику: при создании по умолчанию организация «Торговый дом "Комплексный"», склад «Склад бытовой техники», статус «Согласован» — их нужно менять. Контрагент и договор подставляются сами. Поле `Соглашение` на форме невидимо. Номер вида 0000-000001 повторяется у разных организаций — по номеру документы не искать.
- Поле `Склад` в заказе не принимает `set_value`: `input_text` + `select_from_dropdown` (шаг «выбираю по строке»). Поле `Статус` — сначала `open_dropdown`.
- Номенклатура в таблице `Товары`: `input_text`, затем отдельным вызовом `select_from_dropdown` (в списке представление может быть с кодом «_Абразивная крошка (00-00000339)»).
- «Создать на основании» → «Приобретение товаров и услуг» в списке заказов: кнопка `ПодменюСоздатьНаОснованииОбычное__4`, работает по текущей строке списка; строки/склад/цены подтягиваются из заказа.
- `get_form_analysis(buttons/elements)` на формах документов ERP возвращает 50 тыс. символов (не помещается); для точечных проверок использовать `get_form_element_data`.
- Начальная страница не закрывается через `window_management close`.

## 📌 Полезные шаги
<!-- Проверенные шаги Vanessa Automation / Turbo Gherkin, пригодившиеся при исследовании и написании сценария. -->

- Проверено прогоном (04.10.2026, запуск 3, шаги до проведения заказа): заполнение заказа (`Организация` — точное значение; `Партнер`, `Склад`, `ТоварыНоменклатура` — по строке; `Статус` — точное значение), `таблица 'Товары' содержит строки:` с колонками по заголовкам `Номенклатура`/`Количество`/`Цена` и значениями `'1,000'`/`'100,00'`, `ФормаЗаписать` → `жду, что поле 'Номер' перестанет быть пустым` → `сохраняю навигационную ссылку текущего окна в переменную '…' (Расширение)` → `ФормаПровестиИЗакрыть`.
- `я получаю состояние объекта по навигационной ссылке '$Ссылка$' (расширение)` создаёт булеву переменную `Проведен`: `переменная 'Проведен' имеет значение 'Да'` падает («Ожидали <Да>, текущее <Да>» — разные типы). Использовать `выражение внутреннего языка 'Строка(Контекст.Проведен)' имеет значение 'Да'` (эта замена в прогоне ещё не проверена).
- Рабочая пометка на удаление по ссылке: `я запоминаю навигационную ссылку '…' для удаления (расширение)` + `я устанавливаю пометку удаления объектам, указанным к удалению (расширение)` (проверено, шаги зелёные).
- Локальные переменные (`$НомерЗапуска$`) при `reloadAndRunFromLine` не сохраняются — стартовать нужно выше шага, где переменная создаётся.

## 🚨 Инциденты
<!-- Критические инциденты, которых стоит избегать (потеря записи действий, случайное завершение процесса 1С, неверные пути к скриншотам и т.п.), с датой и кратким описанием. -->

- 04.10.2026: шаг `я помечаю на удаление документы '…' содержащих комментарий '…' (Расширение)` в этой базе (платформа 8.5.1.1343, VA 1.2.043.42, VAExtension 1.32) помечает документы, но затем падает с модальным окном «Значение содержит данные недопустимых типов» (`ЗаписатьJSON`, `ПометитьНаУдалениеПоКомментариюНаСервере`). Если документов для пометки нет — проходит. После падения остаётся открытым окно «VAExtension проведение документа» и модальный диалог (кнопка `OK`). Идемпотентность по комментарию на этом окружении не работает.
- 04.10.2026: приобретение, созданное исследователем без комментария, не находится очисткой по маркеру и блокирует пометку своего заказа («объект расчетов … используется в других объектах»). В созданном на основании документе маркер в комментарий нужно вводить обязательно. Остатки исследования (заказ и приобретение 0000-000001 от 04.10.2026) помечены на удаление.
